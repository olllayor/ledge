Method: four parallel source audits (preferences/native/persistence, clipboard subsystem, shelf/windows/tray/security, cloud sync/teams/billing) cross-checked against the working tree including the uncommitted diff.

Verdict: not ready to release. Core architecture is in good shape. State persistence, IPC validation, window lockdown, and the user-story harness are all solid. What holds the release back comes in two groups: regressions from the uncommitted ShelfView rewrite (drag-out is dead code now, auto-retract ignores user activity) and five security or data-integrity holes in the cloud layer (personal-shelf access control, order-id license escalation, webhook dedupe, team-shelf truncation deletes, plus an always-zero global table scan added in this same diff). None are hard to fix. One focused week covers P0 and most of P1.

Verified clean

What held up under audit, since these were the likely suspects:

  • All six windows run lockDownWebContents: contextIsolation and sandbox on, popups denied, navigations jailed, permissions denied. URL-encoded traversal blocked by resolve-plus-prefix check.
  • Persister writes genuinely atomic: unique tmp name, pre-rename fsync, directory fsync, corruption quarantine keeping three backups, quit-flush with 1500 ms force-quit timeout.
  • Zod validation at every ipcMain handler; preload surface scoped; subscribe unsubscribe leak-free.
  • Category remove, rename, assign paths atomic and race-free versus async capture.
  • osascript invocation is a static string, no injection path.
  • Notch and peek windows are lazy singletons, never constructed simultaneously despite the flag fallback.
  • Tray rebuild idempotent, no menu leaks; drag IPC validated with uuid checks, 64-id cap, synchronous existence check.
