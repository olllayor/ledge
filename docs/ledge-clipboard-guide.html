1. Bug fixes — what broke and what changed

Seven correctness issues plus tightening of two classifiers. Each card shows file, severity, before and after, and how to test it manually.

Critical Schema default mismatch — enabled true vs false
src/shared/schema.ts:180persister.ts:306

The Zod schema defaulted enabled to true while the real app default in defaultClipboardSettings and defaultClipboardSettingsRecord() was false. A bare clipboardSettingsSchema.parse({}) gave true, but a fresh install got false. Docs said enabled, app shipped disabled. Silent mismatch.

Before

clipboardSettingsSchema = z.object({ enabled: z.boolean().default(true), // ← docs truth }) defaultClipboardSettings = { enabled: false }

After

clipboardSettingsSchema = z.object({ enabled: z.boolean().default(false), // unified to false })
  • Unify both layers to false, the actual shipping default
  • No migration needed — existing state.json already has explicit enabled flag
Test: clipboardSettingsSchema.parse({}).enabled === false and fresh StateStore has enabled false
Critical Double save on every copy — prune writes twice
src/main/services/state/clipboardStore.ts:82StatePersister coalescer

Every appendEntry did unshift → prune() → save() where prune() itself saved if it trimmed. Two atomic renames per Cmd+C. updateSettings had the same pattern. Coalescer hid the cost but still two fsyncs.

Before

appendEntry(){ history.unshift(entry) this.prune() // may save this.persister.save(state) // always save }

After

private applyPrune(): boolean { // pure, no save // filter by 30d + limit, return changed } prune(){ if(this.applyPrune()) save(state) } // explicit only appendEntry(){ // dedup then history.unshift(entry) this.applyPrune() this.persister.save(state) // single save }
  • Extract applyPrune() pure function, prune() now only saves for manual prune
  • Callers do one save after prune
  • Fix preserves BUG-001 test: prune still persists when trimmed via explicit path
Verify: Rapid Cmd+C no longer triggers two .tmp-*-rename cycles per copy. Check whenIdle() resolves once per entry.
Critical No dedup — 10× Cmd+C creates 10 dup entries
src/main/services/state/clipboardStore.ts:45getFileBackedPath

Monitor deduped only on changeCount / hash. Copying the same payload again bumps changeCount, so history filled with identical entries. Real clipboard managers dedup and move to top.

Before

state.clipboardHistory.unshift(entry) this.prune()

After

const dupIdx = history.findIndex(e => isSameItem(e.item, input.item)) if (dupIdx !== -1) history.splice(dupIdx, 1) history.unshift(entry) this.applyPrune()
  • Add isSameItem() comparing kind-aware payload: text/code exact, url exact, color case-insensitive hex, file/folder/imageAsset via getFileBackedPath()
  • Found duplicate anywhere is removed and reinserted at top, preserving recency without growth
Test: Copy “hello” three times → history length 1, newest timestamp updated. Copy different text → length 2.
Medium Format hash order-dependent — false change on flipped UTI order
src/main/services/clipboardMonitor.ts:103120 pollOnce

Hash was formats.join('|') raw. macOS can return ['public.png','text'] vs ['text','public.png'] for the same content, triggering a duplicate capture. Also clipboard.availableFormats() throw fallback [] hashed to '', colliding with empty clipboard.

Before

this.lastFormatsHash = snapshot.formats.join('|') const hash = formats.join('|')

After

this.lastFormatsHash = [...formats].sort().join('|') const hash = [...formats].sort().join('|')
  • Sort copy before join in both native and poll paths
  • Order-independent dedup now stable across macOS UTI ordering quirks
Medium QuickPaste shows wrong target when helper down
src/main/services/clipboardMonitor.ts:114QuickPasteWindow

Cache only updated on native notify or poll hash change. If helper was down and poll was still priming (first poll only seeds hash, no snapshot), getLastFrontmostApp() returned null. Palette showed “Press ⌘V if needed” and the previousBundleId === ledgeBundleId guard missed, risking paste into Ledge itself.

Before

getLastFrontmostApp(){ if(!lastSnapshot) return null return {bundleId, name} }

After

getLastFrontmostApp(){ if(lastSnapshot) return cached try { const front = this.readFrontmostApp() if(front.bundleId||front.name) return front } catch {} return null }
  • Fallback to synchronous readFrontmostApp() when cache empty
  • Hotkey right after launch now resolves target app before palette shows
Medium Hex false positive — bare 123456 becomes color swatch
src/main/services/clipboard/payloads.ts:54classifyText

Regex ^#?([0-9a-fA-F]{6,8})$ matches bare 123456 with no #. Classified before code/url, so a transaction ID got a color card. Intent was to support bare hex, but numeric IDs hit it.

Before

if (hexFromText(trimmed)) return 'color'

After

const hex = hexFromText(trimmed) if (hex){ const hasHash = trimmed.startsWith('#') const hasHexLetter = /[a-fA-F]/.test(trimmed) if (hasHash || hasHexLetter) return 'color' }
  • Keep hexFromText permissive for direct calls
  • classifyText now requires hash or at least one hex letter — 123456 → text, aabbcc → color, #123456 → color
Medium Code heuristic noisy + URL never reached
src/main/services/clipboard/payloads.ts:66looksLikeCode

Keyword check function|const|let|import|def|class fired on prose like “function of cell”. And classifier order was color > code > url, so a URL containing function never reached the URL branch and became a code item.

Before

if (/\bfunction\b|.../.test(text)) return true // classifier if(hex) return 'color' if(looksLikeCode) return 'code' if(URL) return 'url'

After

if (keyword && /[=;{}()[\]:]/.test(text)) return true // classifier if(hexOk) return 'color' if(URL) return 'url' // url before code if(looksLikeCode) return 'code'
  • Keyword branch now requires code punctuation
  • Reorder to color > url > code > text
Low Image orphan + thumbnail blocking main
src/main/services/clipboardHistory.ts:62writer.ts:89

Size check happened after payloadToItems already wrote the asset file and bookmark. Rejected oversized image left orphan in assetsDir. Thumbnail also used sync nativeImage.resize on capture hot path.

Before

if(stat.size > MAX) continue // file stays const thumb = makeImageThumbnail(item) // sync

After

if(stat.size > MAX){ broadcastToast(...) await fs.unlink(imagePath).catch(()=>{}) continue } // ... const thumb = item.kind==='imageAsset' ? await makeImageThumbnailAsync(item) : undefined
  • Orphan deleted on rejection and on stat failure
  • Async thumbnail yields one tick via setImmediate before resize, avoiding missed clipboard.changed during rapid copies

3. Architecture — where clipboard sits

Main owns state, renderer only views it. This split is why the fixes are narrow and safe.

Flow Capture → Classify → Persist → View

Swift helper emits clipboard.changed {changeCount, formats, bundleId} → ClipboardMonitor dedupes by sorted hash → ClipboardHistoryService.capture reads via PasteboardReader priority image > file-url > text → classifyText decides kind → payloadToItems writes asset + bookmark → ClipboardStore.appendEntry dedups, prunes, saves atomically → stateUpdated to renderers.

clipboardMonitor.tsclipboardHistory.tspayloads.tsclipboardStore.ts
Safety Zod, atomic write, content hash

All IPC payloads are Zod-parsed. State file writes are temp-file + fsync + rename with dir fsync on macOS. History is local-only, never reaches Convex. New dedup uses content hash, not just format hash. 30-day cutoff is enforced in applyPrune, historyLimit caps after cutoff.

Limitation: state.json is plaintext. ConcealedType skips capture when ignoreConcealedItems true, but past captures stay until pruned. Full encryption would mirror secureSessionStore.ts safeStorage, flagged as follow-up.

4. How to verify — guide for QA and reviewers

Copy these steps. Each maps to a fix.

Checklist Manual QA in 5 minutes
1. Schema default: fresh profile → Preferences → Clipboard shows History enabled off by default. No docs mismatch.
2. Double save: copy rapidly 5×, check ~/Library/Application Support/Ledge/state.json still valid JSON and only one .tmp cycle per copy (watch fs with fs_usage).
3. Dedup: copy “hello” → history 1, copy same “hello” again → still 1 at top with newer timestamp. Copy “world” → 2.
4. Hash order: simulate reversed UTIs in unit test — already covered by monitor_sort.test.
5. QuickPaste target: quit helper (or kill native agent), launch app, immediately hit ⇧⌘V → header shows app name, not “Press ⌘V”.
6. Hex: copy 123456 → Text card, copy aabbcc → Color swatch, copy #123456 → Color.
7. Code vs URL: copy function of cell is … (long prose) → Text, copy https://example.com?x=function&const=1 → URL, copy const x = function(){ return 1 } → Code.
8. Image orphan: copy 26 MB PNG (over limit) → toast “Skipped”, check assetsDir has no new file.
9. Thumbnail: copy 3 images rapidly → pasteboard still captures all three, no missed clipboard.changed.
10. Filters & undo: set filters → chips show count, hit Clear → confirm dialog → Undo → history restored. Scroll 200 items → “Show more” loads next 100.
11. Peek: hover Peek strip → expands, ArrowRight focuses thumbs, Enter copies, file items draggable, text items not.

Next: retention control

Expose 30-day cutoff as setting retentionDays or make it manual-only. Surface in Preferences → Clipboard.

Next: secrets hygiene

On ignoreConcealedItems toggle-on, offer to purge existing history. Consider encrypting history like sync-session.enc or opt-in.

Next: multi-file UX

Today each file in a multi-file copy becomes its own entry. If you want grouped multi-file entries with multi-path drag, spec needed.
